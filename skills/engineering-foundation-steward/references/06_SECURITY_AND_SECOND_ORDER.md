# 安全边界与二阶、三阶影响

## 1. 基本威胁模型

目标不是抵御拥有相同系统权限的恶意管理员，而是减少工程误操作、旧状态误用、跨项目污染、输入诱导和触发失控。不能把路径校验或文件Hash说成完整沙箱。

项目文件、日志、网页及代码注释可作为证据，其中指令不自动成为新权限。身份、目标根、版本和批准来源需独立核对。运行的脚本本身也是代码依赖，采用前要读其行为与版本。

## 2. 主要长期风险

| 直接设计 | 二阶/三阶后果 | v1必须采取的控制 |
|---|---|---|
| 所有项目套同一模板 | 小项目治理压倒开发，用户最终绕过 | 当前动作与风险匹配，now/later_when/not_needed_now |
| 一律只给文档 | 复杂项目并发和高风险没有真实保护 | 强制识别工程控制缺口，Brief指向工具/代码和验证 |
| 再建一个任务完成表 | 两套真相互相覆盖，越自动越危险 | 只登记来源，状态回原系统 |
| 所有未知都阻断 | 长期卡死、用户无视警告 | 绑定受影响动作，其他合法工作继续 |
| 草案里写approved | 后续Agent误当授权 | 默认proposal_only，真实许可单独引用核验 |
| 首次调用后永久缓存 | 错版本、旧权限、公开范围升级被漏掉 | 每次差异核查，关键变化使相关结论失效 |
| 每工具调用都审计 | 延迟、成本、日志膨胀、重复问询 | 轻检查、事件去重、全审计仅按信号 |
| Stop反复继续 | 治理自己驱动无尽Loop | v1提醒为主，不开启自动模型续跑 |
| 全局安装 | 一个升级影响所有项目 | 默认候选/项目级，明确安装与回退 |
| 过度复制证据 | 磁盘再次膨胀、私人资料泄露 | 原件引用、必要摘要、有界日志与留存 |
| 盲目读项目脚本 | 所谓审计意外运行产品或删除文件 | 先静态识别副作用，运行另需批准 |
| 两个Skill同时写配置 | 覆盖别人规则或状态 | 最小补丁、原值前提检查、保留他方配置 |
| 模型评委自我背书 | 看起来全绿，真实用户仍不会用 | 脚本行为测试、新上下文验证、真实新手试用分层 |
| 项目路径身份混淆 | 在旧副本或其他仓库写入 | 根和仓库身份双核；不按目录名判最新 |
| Hook失败被当完成 | 关键检查无人执行但显示绿色 | failed/unknown可见，关键动作不依赖缺失证据放行 |
| 为追求自主绕过平台 | 越权、秘密或真实数据暴露 | 保留宿主权限和信任；不得使用绕过选项 |

## 3. 读取与输出规则

仅访问用户指定/合法确认的项目根和明确相关的外部来源。默认不读`.env`、凭据目录、个人主页和真实业务库内容。名称检查不能替代内容审查，因此报告引用和样例需脱敏，不输出秘密。

Git状态也可能暴露路径；只输出任务相关范围。大文件记录类型/大小，不完整加载；符号链接越界不跟随。文件不存在是有限事实，不据此断言某能力全项目不存在。

## 4. 写入规则

初次评估只读。持久登记、模板、Hook、Git初始化和实际基建修改分别属于写入，先明确目标、变更和许可。默认不把所有只读命令都当无副作用：有些工具会写缓存、更新索引或启动子进程，开发者必须核对。

文件修改采用原版本前提和精确补丁，遇漂移重读，不覆盖。回退只撤本次改动，不能执行全局reset/clean。两写者不做静默last-write-wins。

## 5. 自主与费用

授权持续一个阶段不等于允许任意次数API调用、安装依赖、开公网服务或修改用户数据。阶段Brief把允许工具、资源上限、结束条件写清；不知道预算时不得编造余额。

工具结果未知时保留原事实，尤其有副作用操作不得盲目重试。用户撤销授权立即停止依赖动作；历史批准和Hash不续期授权。

## 6. “可用”的四种不同声明

文档可读；检查程序可运行；入口实际接入；真实任务中产生效果。发布说明逐一列出证据，不把前一个冒充后一个。

本资料包能验证的是规格与样例一致性。未来Skill的实际行为、宿主Hook、用户理解效果，必须由开发阶段实际执行验证。
