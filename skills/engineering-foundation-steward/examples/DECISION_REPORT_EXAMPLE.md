# 完整虚构示例：研究资料工具的两层决定

这是教学合成材料，不是已读取的真实项目或实际测试回执，不授予任何目录权限。假定一次获准只读检查取得下列事实：`README.md`说明本机单写者、仅虚构条目；`catalog.json`是唯一资料状态源；`tools/index.py`能检查并生成`INDEX.md`但直接覆盖；已有旧检查回执，未见可重复运行测试或仓库元数据。版本以该假定快照S0表示。以下展示同一方案`research-basics-01`。

## 用户层

这是一个整理研究条目的本机工具，仍在研究使用阶段，还没有对外服务。你已有资料目录和检查程序，建议保留它们；先补“改坏可找回”和“每次改程序能检查关键错误”两件事，不重建平台。本次只是方案，没有批准或实施。

目前一名AI按你指定的单任务工作，没有并行写入或真实客户资料。本次假定检查覆盖入口、状态文件、生成程序和旧回执；旧回执是否对应现在的程序、完整运行环境和目录之外的资产仍未知。

|现状|能够说明什么|
|---|---|
|catalog.json与已有检查程序|有实现可复用；旧回执不够证明当前全部行为可用|
|README中的接续规则|有文档；新上下文是否照它恢复尚未验证|
|未发现代码版本基线和可复跑测试|在此次范围值得补；不是整项目十项都失败|

**建议一：保存可追溯的代码基线。** 用Git（记录每次代码变化及可恢复版本的工具）只保存获准源码和说明。现在靠手工副本容易混淆哪版程序产生哪次结果；一个本地版本库已经足够，不需远端发布或团队合并平台。暂不做就保留找错版本的风险；加入第二名开发者或需要异地恢复时再考虑远端与审核。Git不备份未纳入的研究资料。

**建议二：给现有程序加失败保护与自动检查，并把运行方法接回原入口。** 在写INDEX前比较刚读过的catalog版本；变了就拒绝覆盖。先完整写临时文件再替换，失败保留旧文件；用虚构临时数据测试正常生成、旧版本拒绝和写入失败。仅加“记得检查”的说明不能验证程序是否破坏旧输出。单写者不需要数据库或常驻Agent；以后允许同时写入时，须再评估锁或受控写入口。更新README只说明原事实源、验证和恢复方法，不另建状态账本。

**你要决定的范围：**推荐一次批准这两项，只新增`.gitignore`、`tests/test_index.py`和本地`.git`，修改`tools/index.py`与`README.md`；测试仅用系统临时目录的虚构条目。catalog.json、现有INDEX及资料保持不动。项目Main唯一写入，不安装新依赖、不上传、不用Hook。成功标准是本地提交可核、正常/失败测试通过且既有条目未变；撤回只反向本次代码/说明补丁并保留资料。

**怎样验收与退出：** 要实际看到获准源码的本地提交、虚构正常输入的正确输出，以及“输入已变化、临时写出失败”时明确报错且原输出未变；这些测试须对应本次代码版本。错误覆盖原输出、未保存版本却报完成、测试未执行，都不算成功。范围内最多两轮普通修复；同因失败无新证据、出现新写者、需要额外权限或无法确定写入结果时先暂停相关动作。你可随时叫停；依据修改前副本仅撤本次代码和说明差异，已有他人改动先核对，新测试可先停用，未批准不删除。现有资料本轮不动；代码撤回不能修复已损坏的研究资料，本轮虚构测试也不保证真实资料可恢复。若改选更轻的方案，先展示它自己的文件、测试与退出范围再确认，不能套用上面的施工许可。

也可以暂不实施，继续阅读和讨论；不要把尚未验证的生成器用于重要资料覆盖。这里没有第二套同样必要的重型方案，不为凑选择推荐数据库。当前无需账户服务、自动调度或全量历史搬迁。

## 工程层：research-basics-01

- **状态/事实：**assessed、proposed；S0为教学假定快照，实际执行者必须核真实根、现有文件字节、父仓库/当前分支/许可。没有这些核验不得将本例直接实施。原catalog仍唯一状态源。
- **建议一对应变更：**核无已有仓库或父库冲突后，仅获批初始化`.git/`；新增默认排除的`.gitignore`，准确纳入`README.md`、`tools/index.py`、`tests/test_index.py`、`.gitignore`。仅本地提交；作者身份缺失集中索取，不推断、不改全局。禁止git add .、push、reset、clean。
- **建议二对应变更：**复用`tools/index.py`的验证与生成函数；读取一次输入字节后计算摘要，替换前确认来源仍匹配；同目录临时写入、原子替换及失败回收。不是完整并发锁。新增`tests/test_index.py`，将输入与输出重定向至系统临时目录，不碰真实catalog/INDEX。README追加唯一事实源、命令、当前证据和复查事件。
- **工具/副作用：**Python标准库、已有Git；写上述5个位置及测试临时目录、Git索引/对象。无安装、网络、其他项目或数据迁移。实机INDEX生成不在本次许可内。
- **验证/失败：**`python3 -B -m unittest discover -s tests -p test_index.py -v`；正常合成生成内容正确，旧摘要拒绝且输出不变，模拟临时写入/替换失败不得返回成功，旧输出字节不变；测试输入缺失显式失败，不空跑。核暂存与提交只有4个叶文件，实际SHA/文件清单可读；没有commit则建议一未完成，不用暂存替代。基线/真实数据被改或测试失败不得标verified_in_scope。
- **责任/授权：**项目Main唯一写者；重要安全写入改动交独立只读Reviewer，Reviewer不写产品。用户未批准时仅回复此方案；用户准确批准后连续执行，报告不产生额外审批。若采用JSON Brief，草案仍proposal_only，引用项目的真实授权记录。
- **返修/停止：**建议用户批准同范围最多两轮普通返修；范围/费用/依赖扩大、并行写者、路径或输入漂移、权限拒绝、未知副作用则暂停相关动作。未批准不得把建议返修额度当成已授权。
- **撤回/复查：**修改前保留获准文本字节/摘要；撤回先核后续无他人改动，只反向本次补丁，不删除已有资料或Git历史。实机数据恢复未测试，不承诺。实施后按两项建议分别回执实际版本、通过/失败/未运行；第二写者、重要真实资料、对外发布或关键失败出现时再评估，日常资料更新归项目自己。

两层都批准同两项机制和同5个位置；没有把用户的简单选择扩大为新数据库、实机资料覆盖或持续调度。
