# Engineering Foundation Steward · 工程基建适配顾问

**项目要开工了，到底该先补什么基础？让 Codex 帮你看清楚，再决定。**

这是一个给 Codex 使用的 Skill（技能说明和配套检查工具）。它会结合你的项目规模、已有成果、数据风险和协作方式，判断现在最值得补的工程基础，并把理由、施工范围、成功标准和退出办法讲清楚。

比如：一个小工具，可能只需要保存代码版本和几条测试；两个 AI 同时改同一份记录，就需要真正防止互相覆盖的代码保护。它不会因为你不懂工程，就给每个项目塞同一套复杂模板。

## 你可能遇到过这些问题

|项目里的困惑|它会帮你做什么|
|---|---|
|“我想做个小工具，但不知道开工前该准备什么。”|找出最低必要准备，区分现在要做、以后再做、当前不需要。|
|“代码已经能跑，换个聊天窗口却接不上。”|检查原入口、实际版本、任务和验证证据在哪里，提出最小接续补强。|
|“AI说做完了，我怎么知道是真的好了？”|把成功变成可观察结果，区分写了代码、跑过测试、通过验证与用户接收。|
|“准备让两个AI一起干，或开始改重要文件。”|提出冲突保护、写入范围、失败检查和独立恢复等必要机制，不能只靠‘记得小心’。|
|“项目已经有自己的台账，难道要推倒重来？”|先复用现有资料和工具，只补实际缺口，不另建一套竞争的任务账本。|

## 你会得到什么

先是一份能用来作决定的用户报告：项目现状、最重要的1～3项建议、为什么这样选、批准后会做什么、怎样算成功、什么时候暂停，以及怎样撤回。

接着是一份给实施AI的工程方案（Implementation Brief）：准确文件和操作范围、验证方式、唯一写者及停止条件。两层说的是同一件事，不会用户只批准一项、工程方案却偷偷多出五项。

方案不等于批准，代码写完不等于测试通过。已有准确授权的小修改则继续执行，不因为调用 Skill 又重新填问卷或重复审批。

## 哪些时候用

- **新项目开工**：确定适度的最低工程基础（kickoff）。
- **老项目补强**：已有成果，但交接、版本或测试有断点（retrofit）。
- **准备一个开发阶段**：明确成果、依赖、授权、验收和停止条件（milestone-charter）。
- **接手或重要变化后**：核对旧约定是否还适用（continuity-check）。

不必记住英文名字，直接描述当前问题即可。普通概念提问或一个错字修改，不需要全套工程检查。

## 第一次试用：先用虚构项目，只读看建议

1. 在上方版本下载页下载 `engineering-foundation-steward-0.1.0-candidate.7-limited.zip` 并解压。
2. 找到里面的 `engineering-foundation-steward/SKILL.md`。保留整个文件夹，不要只复制这一份文件。
3. 在 Codex 提供它的完整路径和一个虚构试用项目的路径，发送：

```text
请读取并使用这个 Skill：<解压后的完整路径>/engineering-foundation-steward/SKILL.md
我的项目是：<一句话说明目标>。
允许读取的项目目录：<准确目录>。
已有产品说明和任务入口：<位置；没有就说明没有>。
本次只读，不修改项目、不运行项目程序或测试、不安装工具。
先复用我已经提供的信息，告诉我最值得补什么、为什么，
以及批准后的成功标准和退出办法。不要先生成一套固定模板。
```

这属于显式读取试用，不等于已经安装，也不证明宿主以后会自动调用。首次不需要配置 Hook（自动提醒）。需要项目级安装时，再确认具体目录和宿主支持的方式，见[接入说明](skills/engineering-foundation-steward/references/RUNTIME.md)。

已有项目可以把目标改为“检查当前交接断点”；准备跨阶段开发时，改为“基于已有成果给出阶段草案”。后续规模、真实数据、写者或自主执行目标明显变化，再做定点复评，不必每次小任务都体检。

## 它负责到哪里

它是工程基建顾问。你的项目 Main（主要实施助手）仍负责日常任务、代码实施、正式状态与验收。

它不会自动批准、长期调度所有 Agent，也不会靠几份 Markdown 就宣称项目已经安全。设计上使用用户提供的项目资料，不要求私人全局记忆或固定六文件模板；跨用户环境的独立验证仍未完成。

## 给想检查代码的朋友

Python 3.9+；部分测试需要已安装 Git。不需要安装第三方 Python 包。在下载的仓库根运行：

```sh
python3 -B -m unittest discover -s tests -v
```

测试只使用虚构临时目录。模型行为评估须另外真实调用，不能用机械测试替代，方法见 [evals/decision_transparency/README.md](evals/decision_transparency/README.md)。

仓库里的 `skills/engineering-foundation-steward/` 是公共 Skill；`tests/` 与 `evals/` 是检查材料。这里不包含开发者的私人项目、聊天历史或全局配置。
